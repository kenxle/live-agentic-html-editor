Principles that changed a choice:

- **Type System Discipline:** `cleanBlock` takes `unknown` and returns a typed result or a typed refusal whose code is `Extract<FailureCode, "RUN_BLOCK_REFUSED">`, so the code stops compiling if the failure table loses it. `BlockWords` is branded and only `blockWords` makes one. `BlockMatch` cannot hold a missing block with leaves or a found block with none, so `runClash` reads a found block's first leaf with no check. A tag is a union on `kind`, so no reader reads attributes off an end tag. `equalsInMode` switches over the two modes with no `default`. The tag tables are `as const` lists with a guard beside each.
- **Test Behavior Not Implementation:** each test states a behavior statement from the spec through the exported functions, with the spec's example inputs and exact outputs. Where I added a test it is for something a caller or a person can see (a clash that must stop at the first block not inside the leaf), not for a private helper.

## Deviations and surprises

- **Four exports the spec does not list, in `html-syntax.ts`:** `tokenizeMarkup` (splits a string into text and tag tokens), `skipDeclaration` (the end of a comment, `<!...>` or `<?...>`), `nbspToSpace` (the three spellings of a no-break space) and `breakOfTag` (a line break for `br`, a blank line for a block, nothing otherwise). Five readers share the scan loop and three share the declaration skip; without these each was a copy. They are domain-internal like `readTag`, each has a test, and the forwarder carries them. `breakOfTag` has the behavior of the `breakForTag` that D2 removes as an export; it is not exported for callers outside the folder. If the orchestrator wants them gone, they fold back into two or three private copies.
- **`MarkupToken`, a type the spec does not list,** goes with `tokenizeMarkup`.
- **The page tree's text node has no `raw` flag.** Nothing read it in the old code. Raw-text elements are handled where the tree is built.
- **`asBlockWords` takes `unknown`, not `string`.** The spec's form (`function asBlockWords(value: string): asserts value is BlockWords {}`) fails `noUnusedParameters`, and `void value` fails `no-meaningless-void-operator`. With `unknown`, the `typeof value !== "string"` check is real, and no cast is involved. For the string `blockWords` hands it, the throw never runs.
- **No-break spellings inside `pre`:** the spec's B34 says text inside `pre` and `textarea` "is kept as written", and the old code turned `&nbsp;`, `&#160;` and `&#xA0;` into a space even there (only whitespace runs were kept). I kept the old behavior: the live-node reader turns a literal U+00A0 into a space in `pre` too, so the two readers agree, and the spec lists no difference for it. No test pins it either way. If the spec means to keep the spellings, it is one line in `clean-markup.ts` and one in `block-text.ts`.
- **A `<` inside a dropped element no longer leaks into `textOf`.** `textOf("a<script>if (1 < 2) x</script>b")` gave `a<b` in the old code, because the "this `<` starts no tag" branch ignored the drop depth. The spec's B44 says the contents of dropped elements are removed, so the new code removes the `<` too. It only shows in the fuzz with comment tags in script contents; cleaned markup never holds a script.
- **Leading breaks are removed in one pass.** The old code stopped after 1,000 iterations, so 5,000 leading `<br>` left 4,000 of them; the new code removes them all, in linear time (tested at 50,000).
- **Control characters go before the no-break references are read,** so `&nb<control>sp;` cannot become `&nbsp;` after the first cleaning and be folded by the second. This keeps `cleanMarkup` idempotent on that input.
- **A raw-text element's end is found with a case-insensitive search of the original string,** where the old code lowercased the whole string once per element. Lowercasing can change a string's length for a few characters, which would misplace the index.
- **Known edge kept, and written in the folder doc:** two spaces on either side of a dropped element or a comment stay two spaces after one cleaning, and a second cleaning folds them. B36 holds for every spec example; it does not hold for that input, as it did not in the old code. Fixing it would change the bytes of stored markup for no caller's benefit.
- **A mutation run lost work once.** I ran the mutation script with uncommitted edits in two source files; its restore step (`git checkout -- <file>`) put those files back to their last commit. I noticed from `git status`, redid the edits and committed before the second run. Nothing from the commits was lost.
- **Playwright wrote no PNGs this time.** `git status` after each browser run showed only `dist/lahe-layer.js`.
- **`docs/tests/index.html` is stale.** It is generated (`npm run docs:tests`) and still lists the three old test files. Nothing checks it. I did not regenerate it because it is not a file this slice owns.
