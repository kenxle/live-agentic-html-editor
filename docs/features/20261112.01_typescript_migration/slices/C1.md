- **Type System Discipline:** the code list is the source of `FailureCode` and the table is checked against it, so a missing row fails to compile; a code's chip offer is one union value (`none`, `copy` or `action`), so "both a Copy button and an action" cannot be written; the three style checks narrow to branded types; `gestureFor` takes a union keyed on the event type and switches on it; the five tool attributes are typed `data-lahe...`. A tool attribute that would not be stripped on capture no longer compiles. Where `satisfies` was refused by `isolatedDeclarations` (TS9010) I kept the constraint with a generic alias that rejects a name outside `data-lahe...` (checked with a scratch compile).

## Deviations and surprises

1. **`src/layer/editing.js` reads `BLOCK_TYPES[].markdown`, and the spec says it does not.** Commit `13fcb421`, one line. See the first section. The spec's caller table was wrong at this one cell, and the browser spec that would have caught it is `free_writing_types`, which passed after the change.
2. **`tolerateStorageQuota(run, report)` accepts `report` as `null` as well as omitted.** The spec's signature has `report?:`, and D7 says to raise an old caller that relied on tolerance rather than restore a guard. `gate:unit` found one: `comments.js` line 1038 builds `onFailure = typeof opts.onFailure === "function" ? opts.onFailure : null` and passes it, and `editing.js` does the same, so `storage_quota_typing.test.js` ("a comment surface with nowhere to report a failure still does not throw") failed with "report is not a function". I did not put back a hidden run-time guard; I widened the parameter's type to `((reported: Failure) => void) | null`, said so in `contract.md`, and added a test (`failures.test.ts`: "a null report is the same as no report..."). When `comments.js` and `editing.js` convert they can pass `undefined` and the `null` can go. Your call whether to keep it that way.
3. **`satisfies` is refused by `isolatedDeclarations`** on an exported constant (TS9010), so the spec's `satisfies ToolAttribute` on the five tool attributes could not be used as written. The constraint is kept with a private alias (`Stripped<"data-lahe-id">`). `ALIASES` is `Readonly<Record<FailureAlias, FailureCode>>` with `FailureAlias` written out, for the same reason; the record type makes a missing or extra alias a compile error.
4. **`FailureName` and `failure()`.** `failure()` and `describe()` take `FailureName` (a code or an alias), because `sync.js` and others still raise aliases; `FailureCode` is the 49 canonical codes. This matters to C4 (below).
5. **Input types are interfaces, not intersections.** The spec drew `GestureInput` as intersections of an object and two interfaces. I wrote `KeyDownInput`, `PointerInput` and `ClickInput` as interfaces extending `Modifiers` and `ReviewState`, and `GestureInput` is their union, so the switch on `type` narrows cleanly. They are exported with the other input types.
6. **`isSendPress` and `isSendEvent` share one internal function** instead of one calling the other with a reshaped object. `exactOptionalPropertyTypes` stops an optional `key` being forwarded as `undefined`. Behavior is the spec's B41 and B42.
7. **Reasons in decisions drop the requirement ids** ("(R7)", "(R17)", "(D3, R13)"). Nothing pins the wording (B29).
8. **Escapes in the new tests.** My first draft of the new tests held a raw no-break space (U+00A0) and a raw bidi override (U+202E). The repo spells these as escapes, so the tests now write them as escapes (the fixes landed in `596a2683`). The same slip put a raw no-break space into `src/domain/gestures.ts`; the spec says the source spells it as an escape, and `67082e0e` fixes it.
9. **The `export_stub.js` question.** The C2 spec once asked C1 to move it; Orchestrator decision 4 settles that it is dead and C1 does not touch it. I did not. It is on the cleanup list.
