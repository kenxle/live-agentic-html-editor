Principles that changed a choice:

- **Type System Discipline:** `SafeId` and `SiteName` are branded and made only by their predicates, so a review id the code has not checked cannot reach `scriptTag` or `newEvent`; `HostClass`, `Handoff`, `Reply`, `CheckResult` and `ReplyParse` are unions on a tag, so `handoffMessage` cannot be handed an argument the Library ignores, a `not_handled` reply always has a reason string, and a passing request check carries a `SafeId`; the route names are unions derived from the four lists; the status table is keyed by every `PROTO_*` failure code, so a code with no status does not compile; `CHECKS` rows must name a code that is in the failure table (or `AUTH_REFUSED`).
- **Test Behavior Not Implementation:** every test states one behavior statement from the spec through the exported functions and constants. Tables (routes, pages, headers, liveness words, the Library's constants) are compared whole against literals written from the spec, not read back from the module. A function whose typed signature refuses a bad value is called the way a JavaScript caller can call it, through one support helper, so the runtime checks the spec keeps are tested.
- **Prove It Works:** the real artifacts ran: `gate:unit`, the layer and Library builds and checks, 16 browser specs, a differential run against the old file, and a mutation run (below).
- **Sequence work into verifiable units:** red tests, then leaf modules, then the dependent ones, then the reply parser, then each noticed fix on its own, then the switch, then the cuts.

### The differential run

For each function it feeds the old and new versions generated inputs (every origin grid, a Host grid of 3,624 cases, 12,000 random request-check combinations, 20,000 reply lines, 4,000 script-tag option sets, every command with every state dir, every liveness state and wait) and compares the answers. Every difference is one the spec lists or one for a value the types now refuse:

| Difference | Count | Why |
| --- | --- | --- |

| the reason lists a field once | 12,392 | D7 |
| a reply with a required reason or text that is not a string, together with another failure | 46 | D6, in which the refusal that wins depends on the order of the checks |
| an Origin header given as a list on an open route comes back as text | 687 | the new type says text |

## Deviations and surprises

1. **Five old cases the spec did not map.** Running the gate found them.
   - `build_layer.test.js` ("the Library page bundle holds the protocol...") named `src/shared/protocol.js` and said the Library page has no failure codes. I changed the path to `src/contract/protocol.ts` and dropped "and not the failure codes" from its title, because D12 is that the bundle now has them. The test still asserts only the manifest's entry list.
   - `manifest_library_files.test.js` named the old path. Same one-word change.
   - Three tests assert on the route table's strings, which D5 removes: `target_mtime.test.js` (`replies.poll` documents `target_mtime` and `page_path`), `quiet_tab_polling.test.js` (`window.claim` documents `quiet?` and `quiet_heartbeat_seconds`) and `agent_liveness.test.js` (`replies.poll` documents `agent_liveness` and `oldest_unanswered_at`). Their point is that nobody has to read the handler to find these. I moved the same assertions to the route table in `docs/ongoing/code/contract.md`, through one helper (`test/helpers/contract_doc.js`), and the `replies.poll` row there gained the `agent_liveness` field list the old string carried. This is the S0b pattern for a source-text test. The spec said nothing about these three, so tell me if you would rather they went to the board.
2. **The forwarder copies the exports.** The spec writes `module.exports = require("../contract/protocol.ts")`. `docs/ongoing/code/README.md` says a module the browser also loads gets `Object.assign({}, require(...))`, because old code and tests replace functions on it, and the protocol is loaded by the browser. I followed the README, as C1 did.
3. **`checkRequest` is one function with the checks in order, not a list.** The spec asks for "one ordered list of small pure checks". The first version of the list had no honest way to hand the matched review to the success result without a branch that could never run, so the checks are `if`s in the order they run, with small helpers. The behavior is the spec's, and `contract.md` says so.
4. **Constants built from other constants cannot be inferred.** `isolatedDeclarations` refuses `as const satisfies`, `AUTH.NONE` and `BASE + "/health"` in an exported constant (TS9010, TS9013), so the route tables spell paths and auth modes as literals, `CATALOG` and `MONITOR` carry a written type, and each list is checked against its entry shape where the route-name union is built. A test pins that every API path sits under `BASE`. The error body's check and the Library's `CATALOG_LOG` stay literal because `scripts/catalog_opens.py` reads `CATALOG_LOG = {` and `PREFIX:` from the text.
5. **The bundle test cannot boot the whole layer.** The layer's last file boots against a real document, so a unit test cannot load the full bundle. `protocol.test.ts` builds the protocol entry exactly as the manifest places it (`builtFiles()` up to it for the layer, `libraryFiles()[0]` for the page) and checks the registered names in both. The browser specs load the real bundles.
6. **`docs/CONTRACTS.md`, four lines.** `protocol.CATALOG_LEGACY_NOTE`, `AGENT_LIVENESS.handoffMessage(...)` twice and `protocol.AGENT_LIVENESS.overdue` now name the new functions. `docs/tests/index.html` is generated by `npm run docs:tests` and still names `AGENT_LIVENESS.handoffMessage` in one header; I did not regenerate it.
7. **`parseEventLine` on a non-string.** It still never throws: `JSON.parse` coerces and a failure is a "not JSON" reason.
