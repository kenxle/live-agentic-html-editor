# Wireframe decision

**Direction A (block menu on the bar) is approved.** Ken approved it after clicking through all three directions on the wireframe review.

## What Ken said about each direction

- **A. Block menu on the bar:** "this looked great."
- **B. Type like Markdown:** "i liked the style of the insert better on the first one, not this one. the idea of markdown in the editor is interesting, but i like hotkeys and ui just as much."
- **C. Growing frame, gutter plus:** "no this is too busy for the main doc."

## What carries into the build

- A's "+ Write here" line for starting in empty space, and its block-type menu on today's bar.
- Markdown shortcuts stay as an extra, because Ken found them interesting. Hotkeys for each block type are added, because he wants hotkeys and buttons as much as Markdown typing.
- One sitting is one edit and one rail card. Ken settled this on the brief before the wireframes, and all three directions show it.
- C's "+" in the margin and the bar on the frame's bottom edge are out.

## The workflow itself

Ken made no comment on the order of the steps. The core path stands as drawn:
1. enter edit state
2. hover and click "+ Write here"
3. pick a block type, then type
4. leave editing
5. the card waits for the agent
6. the agent places the text, then offers proofreading
