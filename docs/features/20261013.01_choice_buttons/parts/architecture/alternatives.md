Each entry names what was chosen, what was rejected, and why. Read this before deviating.

- **A `choice` field, not words in `note`.** A press could have been a comment whose note reads "promote". Rejected: `note` is free text, the agent would parse it, and the identity would ride on the anchor. The `choice` field is bounded tokens the agent reads as data, and the group id is the agent's own.
- **An explicit `data-lahe-document` attribute, not inference from the script src.** The layer could tell a helper-served page from a `lahe add` page by whether the tag's src is the library path on the page's own origin. Rejected: an inference from a URL shape is a rule nobody can read, and a future serving change would silently flip it. One attribute the helper writes is testable and visible in the page source.
- **Find the group by its id, not by the anchor ladder.** The ladder (stamp, text, tie-breakers) exists for text the reviewer selected. A choice group has an id the agent wrote on purpose, so the re-mark pass matches on it exactly and refuses two matches. The anchor is still minted on the group element, for the card's "show me where" and the heading, and nothing more.
- **The agent writes the decision into the source; the layer only marks the DOM.** The layer could write `data-chosen` into the page itself, but a rebuild drops it. Having the agent carry it into the source is the same move the stamp round makes with `data-lahe-id`, it keeps the record as the truth, and it is what lets a page show its decisions with no Lahe present (the one thing worth taking from the checkbox approach).
- **No new lifecycle state.** A "pressed" state was considered. Rejected: a press is a draft that is ready in the same tick, which the table already allows, and the reword path already models changing one's mind. A new state would touch the merge rule, the projection, and every card.
- **A raw HTML block, not a Markdown shorthand.** A fenced `::: choice` block the renderer turns into the component would be shorter to write. Rejected for now: marked passes HTML through already, the same block works on an agent's HTML page, and the renderer stays untouched. If agents get the block wrong in practice, a shorthand can be added later without changing the record.
- **Real `button` elements, not styled divs.** Keyboard, focus ring and screen readers come free. The page's own click handling is irrelevant on a document page.
- **Approach A (a button that posts a comment) and approach C (task-list checkboxes)** were rejected in [the crucible](../../00_crucible_choice_buttons.md): A fails on repeated buttons, C is Markdown-only and not exclusive.
