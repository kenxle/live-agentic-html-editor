Summary

Four workstreams, five pull requests. core moves page serving into the helper behind a switch, rewires every helper module to the new name registry, then makes it the default and retires per-session page servers. library points the Library at stable addresses. install adds the login item and always-on behavior on three systems. lahe-names adds the optional .lahe ending on macOS. Docs, the skill, and the contract change in the same pull request as the behavior they describe.

Steps

Workstream: core (Steps 1 to 3)

Outcome: the helper serves every page Lahe serves itself, at <name>.lahe.localhost:<port>/<path>, with today's paths, today's rail rules, and no per-session page-server process. Behind the LAHE_PAGES=sites switch until Task 3.1 makes it the default.

Reads first: the architecture (Summary, Data / State Changes, Key Flows "Serving a request", "Which review answers on a page", "Binding"), recon sections 1, 2, 5, 9, docs/ongoing/SERVING_ARCHITECTURES.md, docs/ongoing/STATIC_SITE_FOLDER.md, docs/ongoing/FREE_WRITING.md (notes pages), docs/CONTRACTS.md (D11 checks), docs/diagrams/module_map.md. Not the alternatives leaf, not the review files, unless weighing a deviation.

Authority: the architecture. A deviation goes under Changes from plan on the progress page, with a one-line question to the orchestrator first.

Step 1: Named sites behind a switch

Task 1.0: Spike, *.lahe.localhost in the three Playwright lanes. Prove that Chromium, Firefox, and WebKit in this repo's Playwright setup load http://x.lahe.localhost:<port>/ from a helper bound to 127.0.0.1 and ::1, locally on macOS and in CI (Linux). Record the result and any launch flag needed in progress/phase6_workstream_core.md. Acceptance: one throwaway spec passes in all three lanes, or the gap is reported before Task 1.4.

Task 1.1: The registry (src/service/sites.js). Name rule, clash rule, reserved names, realpathSync.native roots, modes, mounts, worktree recording from the .git file, sites.json plus the append-only sites.log, rebuild from the log, read-only mode when neither reads. Single writer: only the helper process calls the writing functions. Acceptance: unit rows V1 to V6.

Task 1.2: Host dispatch and listeners (index.js, protocol.js). Host dispatch runs before OPTIONS and catalog matching. Grammar per the security notes. Second listener on ::1, failure logged. PAGES constants and Host rules live in src/shared/protocol.js. Acceptance: V7 to V10.

Task 1.3: Page serving (src/service/page_routes.js). Move the serving half of static_servers.js: path safety, hidden-file refusal, page-only mode, injection (with data-lahe-aliases), Markdown render from source with a file-time cache, site-scoped mounts, reserved files, Cross-Origin-Resource-Policy, the unknown-name and file-gone pages, the read-only worktree copy. The review rule per request, without the session filter. Acceptance: V11 to V20.

Task 1.4: Binding and the CLI order. site.bind route with the CLI secret file, refusal of any Origin, root from the request. add --served-by-helper. lahe review, lahe write use the new order when LAHE_PAGES=sites. Old loopback origins removed at bind. The Origin check for page requests reads the registry. Acceptance: V21 to V25.

Step test: with LAHE_PAGES=sites, lahe review on an HTML file, a Markdown file with an image and a link outside its folder, a folder, and lahe write each print a .lahe.localhost address. Each page loads with its rail, and a comment round-trips to review.json.

Step 2: Every helper module asks the registry

Task 2.1: Page-to-file mappers. reviews.js (servesPath, healing stand-down, pageUnderFolder, targetForPage), heal.js, rebuild.js, handled_check.js, projection.js, markdown.js, markdown_links.js, linked files. Each reads sites instead of page-server records. Acceptance: V26 to V30.

Task 2.2: Old comments and grouping. Aliases computed from old page-server records at serve time. samePage in src/shared/record.js and grouping in src/shared/review_format.js accept them. Acceptance: V31, V32.

Step test: the same reviews as Step 1, plus a review created before the switch, reopened under the switch: its old comments show, an agent reply reloads the page, a handled check reads the right file, and no served HTML file on disk changes after a poll.

Step 3: Make it the default, retire page servers

Task 3.1: Flip the switch. Sites become the only path for HTML, Markdown, folders, and notes. Page-server spawning, the idle sweep, the session-close stop, port history, origin swaps, and the SIGHUP mount reload are removed. Old records stay readable. Every helper start stops leftover page-server processes named in old records. lahe session close stops only the session. Remove LAHE_PAGES. Acceptance: V33 to V36, V63, V64.

Task 3.2: lahe status and printed lines. Status shows the port, the printed ending and why, and the site name for each review. No line mentions an idle-stopped port. Acceptance: V37.

Task 3.3: Skill, contract, and serving docs. skills/lahe/SKILL.md, the contract in src/shared/review_format.js and its two restated copies (test/unit/review_format.test.js, docs/CONTRACTS.md), docs/CLI.md, docs/ongoing/SERVING_ARCHITECTURES.md, STATIC_SITE_FOLDER.md, FREE_WRITING.md, SESSION_OWNERSHIP.md, docs/diagrams/system_overview.md, session_ownership.md, review_round_trip.md, module_map.md, src/shared/manifest.js, and the D11 residual line. Then npm run install-skills. Acceptance: V38.

Step test: full npm run gate alone, 0 failed. The leak check counts no static_servers.js --serve process left by any test.

Don't touch: src/service/catalog_*.js, src/layer/catalog/, src/cli/commands/install.js, src/service/login_item.js, src/service/name_server.js.

Task 4.3: Docs. docs/ongoing/LIBRARY.md and the Library parts of docs/diagrams/system_overview.md and session_ownership.md. Acceptance: V38 (Library part).

Workstream: install (Step 5)

Outcome: lahe install makes the helper start at login and restart if it stops, on macOS, Linux, and Windows. Installed, the helper never stops itself, the CLI never spawns a second copy, and a stale helper is replaced at a quiet moment.

Reads first: the architecture's "Always-on lifetime" and "Login item per system" sections, Security notes (install hygiene), scripts/install-cli.js, src/service/self_stop.js, startHelper in src/cli/commands/session.js and its copy in add.js, docs/INSTALL.md.

Authority: the architecture. The spikes in Task 5.1 may change a mechanism; report before building on a changed one.

Task 5.1: Spikes, one per system. For macOS (launchd agent with KeepAlive, the Background Items notice), Linux (systemd --user unit), and Windows (Task Scheduler XML with restart on failure and a hidden window), prove install, start at login, restart after a kill, and uninstall on a throwaway state folder and port. macOS is run on this Mac. Linux and Windows run in CI jobs that never fail the run (continue-on-error, verdict in the log), per CLAUDE.md's CI rule. Acceptance: a written verdict per system in progress/phase6_workstream_install.md.

Task 5.2: lahe install and lahe uninstall. src/cli/commands/install.js, src/service/login_item.js, install.json with the resolved state folder and port, the login item passing --always-on --port --state-dir. Refuses without a terminal and when run as root. Warns on a computer with more than one interactive user. Registered in src/cli/index.js. Acceptance: V45 to V48.

Task 5.3: Always-on behavior. --always-on turns self-stop rule 1 off and keeps rule 2. /health reports a state-folder id. When install.json exists, both startHelper copies ask the login item instead of spawning, and compare source stamps against the clone the login item names. A stale helper is replaced at a quiet outbox moment with windows open. Acceptance: V49 to V52.

Task 5.4: Idle cost (brief requirement 11, light when idle). Before building, write the two limits in progress/phase6_workstream_install.md: memory and wakeups per minute with nothing open, and with Ken's usual tab count (read from his browser) overnight. Measure today's helper plus page servers, then the always-on helper, with the existing scripts/measure_idle_requests.js style. Raise NumberOfFiles in the plist only if the measurement calls for it. Acceptance: V53.

Task 5.5: Docs. docs/INSTALL.md, README.md, docs/CLI.md (install, uninstall), and the always-on lines in SESSION_OWNERSHIP.md. Acceptance: V38 (install part).

Don't touch: page_routes.js, sites.js, catalog files. session.js only in startHelper; core owns session close.

Workstream: lahe-names (Step 6)

Outcome: on macOS, lahe install --lahe-names makes every site also answer at <name>.lahe, and only after the helper has proved its own name server answers .lahe lookups. What lahe review prints follows Ken's answer to the open question on the printed ending.

Reads first: the architecture's ".lahe on macOS (opt-in)" section, Security notes (DNS rebinding, name server), the brief's questions leaf (the printed-ending question and Ken's answer).

Authority: the architecture, plus Ken's answer at the review gate. Depends on install Step 5.

Task 6.1: The name server (src/service/name_server.js). Loopback UDP on the port from install.json. Answers A 127.0.0.1 and AAAA ::1 for names under .lahe, REFUSED otherwise, drops malformed packets without throwing. Started only when install.json records the resolver. Acceptance: V54, V55.

Task 6.2: Resolver setup and verification. --lahe-names writes /etc/resolver/lahe with fixed content and a Lahe marker in one sudo call, no shell interpolation. The helper verifies at start and every 5 minutes with a fresh random name it must see itself. Page routes accept .lahe Hosts only while verified. Uninstall removes the file only when it carries the marker. Acceptance: V56 to V59.

Task 6.3: Only if Ken chooses .lahe as the printed ending. Copy fallback in src/layer/export.js and overlay.js (the Library's ships in Task 4.2 either way), a local-storage lease when Web Locks is missing in src/layer/store.js, and page-type detection from Accept when Fetch Metadata is missing. Acceptance: V60 to V62. If Ken keeps .lahe.localhost printed, this task is dropped and the rows are marked not applicable.

Acceptance Criteria

Standard (every feature inherits these; keep them verbatim):

    • Clear visual hierarchy and information architecture. You know where to look, and the page's organization makes sense.
    • Consistency with the rest of the app. Buttons look like our other buttons, hover states follow the same convention, primary and secondary carry the same color meaning they carry elsewhere.
    • Honest feedback. Toasts and status messages report what actually happened. Never an optimistic "done" for something still in flight, or something that failed.
    • Micro-animations that mean something. Motion signals state or direction; it isn't decoration.
    • Copy in the brand voice (the project's brand or voice doc).
    • Existing components reused and the style guide followed. Nothing reads as a stock framework default.
