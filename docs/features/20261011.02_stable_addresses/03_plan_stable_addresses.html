Summary

Four workstreams and five pull requests:

  • core moves page serving into the helper behind a switch, has every helper module ask the new name registry, then makes it the default and retires per-session page servers.
  • library points the Library at stable addresses, alongside core, behind the same switch.
  • install adds the login item and always-on behavior on three systems.
  • lahe-names adds the optional .lahe ending on macOS.

Docs, the skill, and the contract change in the same pull request as the behavior they describe. Builders work on branches off one integration branch (feat/stable-addresses). "Merged" in this plan means merged into that branch, and a PR is cut from it once its steps are green.

Step 0: Orchestrator setup

Task 0.1: A dispatch-only CI workflow, landed on main as its own small PR. The workflow runs a named ref on Linux and Windows. Each step has continue-on-error, and the verdict goes to the log. It never runs on push, so it never sends Ken a failure email. It exists for the spikes in Tasks 1.0 and 5.1, and is removed in cleanup.

Task 0.2: The idle-cost baseline. Before PR 2 lands, measure today's helper plus page servers, as Task 5.4 describes.

Every builder's contract

Each workstream leaf below is a builder's packet, together with this block, the brief's Requirements, and the verification rows its tasks name.

  • Never delete a file. No rm, no git clean. List anything to remove under "To delete at cleanup" in your progress file.
  • Tests: run npm run gate:unit. You may also run one named browser spec with npx playwright test test/browser/<file>. Never run the whole browser suite; the orchestrator does that once per checkpoint.
  • Leaks: run ps -axo command | grep -c "[l]ahe.js serve" before and after your test runs, and report both numbers. Every helper, listener, name server, and login item a test starts is stopped in teardown. Tests use free ports and a temp state folder, never 7817 or the real state folder. They never touch the real login item or /etc/resolver.
  • Do not commit dist/. Put a local rebuild back with git checkout -- dist/lahe-layer.js.
  • Manifest: add each new src/ file to src/shared/manifest.js in the same commit.
  • Screenshots: a change anyone can see (the Library, the unknown-name and file-gone pages) gets light and dark screenshots from the test run, on your progress file.
  • Hand back: your branch; progress/phase6_workstream_<name>.md with what you built, the rows that pass, the leak counts, and any deviation; and a self-review against the engineering principles.
  • Stop and ask in one line when you hit a limit, or when the architecture does not fit the code. Do not document around it.

Steps

Workstream: core (Steps 1 to 3)

Outcome: the helper serves every page Lahe serves itself, at <name>.lahe.localhost:<port>/<path>, with today's paths and rail rules, and no per-session page-server process.

Reads first: the architecture's Summary, Data / State Changes, and Key Flows ("Serving a request", "Which review answers on a page", "Binding"); recon sections 1, 2, 5, 9; docs/ongoing/SERVING_ARCHITECTURES.md, STATIC_SITE_FOLDER.md, FREE_WRITING.md (notes pages); docs/CONTRACTS.md (D11 checks); docs/diagrams/module_map.md.

Step 1: Named sites behind the switch (PR 1)

The switch. LAHE_PAGES=sites is read by the helper at start and reported in service.json. The CLI follows the running helper's value, never its own environment. Live for everyone in PR 1, because each is harmless with no names granted: Host dispatch, the ::1 listener, the site.bind route. Behind the switch: lahe review and lahe write binding instead of starting page servers, and every registry-backed lookup.

Task 1.0: Spike: *.lahe.localhost in the three Playwright lanes. Locally on macOS with npm run gate:all's three lanes, and on Linux through the dispatch workflow from Task 0.1. Record any launch flag needed. Acceptance: a throwaway spec loads a page in all three lanes, or the gap is reported before Task 1.4.

Task 1.2: Host dispatch and listeners. In index.js, with rules and constants in src/shared/protocol.js. Acceptance: V7 to V10, V68.

Task 1.3: Page serving, src/service/page_routes.js. The serving half of static_servers.js moves here, plus everything the architecture's "Serving a request" flow adds. Acceptance: V11 to V20, V69.

Task 1.4: Binding and the CLI order. site.bind, the CLI secret, add --served-by-helper, and the new order in lahe review and lahe write. Old loopback origins are removed at bind. The Origin check for page requests reads the registry. Acceptance: V21 to V25, V65, V66.

Step test: with the switch on, lahe review on an HTML file, on a Markdown file with an image and a link outside its folder, on a folder, and lahe write, each print a .lahe.localhost address. Acceptance Criteria

Standard (every feature inherits these; keep them verbatim):

    • Clear visual hierarchy and information architecture. You know where to look, and the page's organization makes sense.
    • Consistency with the rest of the app. Buttons look like our other buttons, hover states follow the same convention, primary and secondary carry the same color meaning they carry elsewhere.
    • Honest feedback. Toasts and status messages report what actually happened. Never an optimistic "done" for something still in flight, or something that failed.
    • Micro-animations that mean something. Motion signals state or direction; it isn't decoration.
    • Copy in the brand voice (the project's brand or voice doc).
    • Existing components reused and the style guide followed. Nothing reads as a stock framework default.

Summary

Two blockers, both about the app being broken on main between pull requests:

  • PR 2 retires page-server spawning, but the Library's Open still restarts page servers until PR 4. Library Open is broken on main in between, and the V36 row (no code spawns a page server) cannot pass in PR 2.

PR12. Leak risks new to this feature

severity   important
kind       risk
area       test plan
where      Test List callout; Tasks 5.1, 5.3; V10, V48, V49, V51, V54
  • what The table's callout says every process is stopped, but four new ways to leak are not addressed:
    • The macOS spike in Task 5.1 loads a real launchd agent with KeepAlive on Ken's Mac. If uninstall is skipped or fails, launchd restarts the helper forever, and once the temp state folder is gone, self-stop rule 2 plus KeepAlive is a restart loop.
    • --always-on turns off self-stop rule 1, so any test helper started with it never stops on its own.
    • The helper now has two listeners. If shutdown closes only the 127.0.0.1 one, the process stays alive.
    • V51 restarts a stale helper "through the login item". In a test there is none, so something stands in and spawns a helper the test does not own by pid.
    • V54 and V55: a name-server test on a fixed port collides across parallel workers (AR18).
  • why The 2026-10-07 incident (1,892 leaked helpers) came from exactly this kind of "the process outlives the test" gap.
  • fix Add to the rows: V48 renders the plist, unit, and task XML and never loads them. Task 5.1 runs uninstall in a finally and checks launchctl list for the label before and after, with both outputs on the progress page. Add a U row: stopping a helper closes both listeners and the process exits. V51 names its stand-in login item and stops what it spawns by the pid in service.json. V54 uses a port from free_port.js.
