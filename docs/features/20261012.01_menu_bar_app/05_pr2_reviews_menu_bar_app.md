## Code review

One real bug in the Swift app, one coverage gap that matters, one certain but rare bug. The rest of the diff checked clean against the docs.

**Important**

1. **A negative Content-Length crashes the app before the signature is checked.** `macos/menubar/LaheMenuBar.swift` lines 655 to 657: `Int("-1")` parses to -1, passes `declared <= body.count`, and `Data.prefix(-1)` hits a precondition and stops the process. `parse` runs before `replyChecks`, so any program on the API port can crash the app while the helper is down, and the login item restarts it after a crash: a loop every 10 seconds with a crash report each time. Fix: require a non-negative value (or parse as `UInt`). Test red first: a self-test case `parsed("HTTP/1.1 200 OK\r\nContent-Length: -1\r\n\r\n{}") == nil`, which today traps the self-test process.
2. **`npm run gate` never runs the hand-written socket client against a live server.** `scripts/check_menubar.js` builds only the real-label binary and runs `--self-test`, which covers `Wire.parse` on strings but not connect, send, the read loop, timeouts or the live signature check. Those are in `test/unit/menubar_app.test.js`, which skips unless `LAHE_MENUBAR_APP` is set. Suggested fix: `check:menubar` also builds a `-D LAHE_TEST_LABELS` binary and runs the two non-launchd cases, which already stop what they start.

**Below the bar**

3. **A failed rebuild can mark the wrong source as failed.** `src/service/menubar.js` lines 397 to 402: `rebuildNow` records `last_error.source_stamp` by reading the clone's files again after the failure. If the source changed during the compile, the new source is recorded as "failed before" and `tick` never builds it. Fix: `build()` returns the stamp of the copy it compiled. Test: a fake runner whose swiftc call rewrites the source and exits 1; the next `tick` rebuilds.

**Checked and sound:** the proof (random nonce from `arc4random_buf`, CryptoKit constant-time compare, uppercase and malformed hex refused, different prefixes for request and reply, secret reread after a 401 or a bad signature); the socket (one `close` in `defer`, `SO_NOSIGPIPE`, one 4-second deadline, a 4 MB cap, its own serial queue); Node's HTTP/1.0 answer (no Content-Length, connection closed); the summary's memory (synchronous appends, `onAppend` after the line is on disk, the beat once per 15 seconds, `foldOnce` off the watch list afterwards, no way found for the count to stick); Stop and Start (constant labels and plist path, a test build accepts only a digits-only id, `startThroughItem` refuses before any command); test cleanup.

**Minor, no action:** the README's claim that an unchanged answer is not decoded (the real helper's `generated_at` changes every poll); a V17 test named "within one beat" now waits 40 beats.

## Security review

Two important, three minor. The proof wire, the address allowlist, the logging and the Stop path's launchctl calls hold up.

1. **Important. The Stop hold can be ended by ordinary lahe commands.** Every helper start deletes `stopped.json` (`src/service/index.js` line 1180), and two paths start a helper without checking the hold: `lahe serve --always-on` skips the "installed here?" check, and `lahe add --port <other>` (or `session` with another port) gets no record from `installedFor` and spawns `serve` directly. One agent command ends the hold for everyone and a second helper runs on the state folder. SR7 promises no lahe command starts the helper while the hold stands. Fix: `serve()` refuses with the stop message while the marker stands unless the login item launched it at login (`--always-on` plus `XPC_SERVICE_NAME` equal to the label, which launchd sets); only that path clears the marker. Test red first: install.json (port P) and stopped.json in a temp folder; `add --port Q` and `serve --always-on --port Q` exit non-zero with the message, nothing answers on Q, the marker stays.
2. **Important. A bad Content-Length crashes the app before the signature is checked.** The same finding as the code review's first; the squatter can be another user's process on the same Mac.
3. **Minor. While stopped, the app keeps handing fresh proofs to whatever holds the port.** The app knows the hold stands but sends a signed request every 5 seconds. Each proof is valid 30 seconds and a freshly started helper has an empty nonce cache, so a squatter that lets go of the port as Start runs can replay the latest proof once and read the summary (titles, path hints, session names). Fix: while the hold stands, send nothing and show "Stopped by you" from the marker. Test: with stopped.json and a plain TCP listener on the port, `--watch` for two polls sees zero connections.
4. **Minor. The menu bar commands act on the real `lahe-menubar` job from any state folder.** `removeApp`, `rebuildNow`'s restart, `isRunning` and `tick` use the fixed label and plist path whatever folder is named. `lahe uninstall --state-dir <copy>` unloads the real job and deletes the real plist; a rebuild or an always-on helper on a copy kickstarts the real app. The production app pointed at a copy unloads the real helper but writes the marker into the copy. Fix: before any launchctl call on the fixed label, compare the plist at the fixed path with `describeApp(spec).contents` for this folder; if they differ, touch only the files. Test: two folders A and B with one fake home; install in A; `removeApp` and `rebuildNow` on B leave A's job alone.
5. **Minor. The summary's reply check follows symlinks.** `settledKey`, `replySignature` and `statMtime` in `src/service/summary.js` use `statSync`, so a symlinked `replies-*.jsonl` to a busy file re-folds that review every beat. No contents are read (`replies.discover()` skips symlinks). Fix: `lstatSync` and skip anything not a regular file. Test: a reply-named symlink; touch the target between beats; `foldReplies` is called zero times.

**Checked and clean:** the reply proof (nonce, status and body hash, constant time, uppercase or missing headers refused); 16-byte nonces and millisecond timestamps; the secret never sent; the Stop path's launchctl calls (constant label and plist path, `/bin/launchctl` absolute, arguments as an array, nothing in the state folder chooses the job, a production build refuses `--action`); the allowlist (SR4, the address rebuilt from parsed parts); logging (review ids, error codes and swiftc output only); the build (fixed file list, lstat on each, hash of the copy, swap in only on success); the plist checks before bootstrap; the summary answer (exactly the fields in CONTRACTS.md, no comment text or absolute path).

## Staff design eye

Verdict: not ready to ship as drawn, but the fixes are small. The icon and the menu's structure are sound.

**What already works:** a template image with the count drawn in, so it inverts correctly when highlighted and in dark mode; monospaced digits; "99+" crisp at 1x in both appearances and close to the clock's weight; "can't tell" (outline plus "?") and "not running" (outline with a slash) distinct from each other and from the filled states; the icon never falls back to a stale number; the section order follows urgency; Hide and Stop split instead of a plain Quit; the stopped state says who and when.

**Must fix before ship**

1. **The real menu has no visible section headers, and the snapshots hide this.** `rebuildMenu` makes every header a plain disabled `NSMenuItem`, so "Waiting on you: 2", "12 more", "Lahe is not running" and the empty-state lines are all the same grey 13 pt text; only the `--snapshot` drawing shows headers small and semibold. Fix: `NSMenuItem.sectionHeader(title:)` on macOS 14, an `attributedTitle` in a small semibold secondary-colour font on 13, and the snapshot follows the same code path.
2. **"(open, 1 question, 3 unread)" is ambiguous twice:** questions are counted inside unread (readers add them to 4), and "open, 1 question" reads as "open question". Fix: drop "open" from the waiting rows; say "3 unread, 1 is a question".
3. **"Connected sessions: 2 (5 open)" clashes with "Open documents" above it.** Open-but-idle sessions are the stray sessions the brief wants found in one click, hidden in a parenthetical. Fix: header "Connected sessions: 2", a note row "21 other sessions still open" with a Library tooltip; drop "(0 open)" from the empty state.
4. **The Hide tooltip is false when Lahe is not running ("Lahe keeps running"), and shows raw backticks.** Fix: a separate tooltip for those menus; no backticks anywhere.
5. **"Lahe was updated; rebuilding" can become a permanent false claim** after a failed rebuild. Fix: "Lahe was updated. This icon is out of date." with "If this stays, run lahe menubar rebuild."
6. **Stop Lahe is one row from Hide, with no confirmation, and it breaks every agent.** Smallest fix: an alert "Stop Lahe? Agents' lahe commands will fail until you start it again." with Stop and Cancel. The brief asks for that sentence as a line under Stop; the alert could carry it instead. Ken's call.
7. **The many-documents fixture contradicts itself** (open documents count 3 with "14 more"; connected 2 with "3 more"; agents 4 with "2 more"), so the 8-row cap is never drawn. Fix: each count equals rows plus `more`, at least 9 per capped section; the agents overflow row says "2 more documents".

**Needs Ken's call:** Waiting on you has no row limit, so 120 documents make a menu taller than the screen with Hide and Stop below a scroll arrow (suggestion: about 15 rows then "N more: open the Library"; the brief says never cut short, Ken's decision). The icon uses the retired speech bubble, the most generic shape in a menu bar, against the brief's "the Lahe mark, not a generic symbol"; an outlined document glyph with a folded corner would match the tab icon.

**Nice to have:** outline at rest and filled with the count, `appearsDisabled` for not running and can't tell; the slash direction and a gap around it; the width change at "99+" (about 27 pt); "No recent documents" or no header in the empty state; merge the two empty lines; Recent leaves out documents listed above; "(focused)" to "(front tab)"; no raw session id; "Lahe had an error (500)"; update titles in place while the menu is open instead of rebuilding under the cursor; a beep or Library fallback on a failed click; truncation by width, no space before the ellipsis, collapsed double spaces; a separator before Connected sessions; parallel header wording; "Stopped by you on Oct 20 at 11:41 AM"; the VoiceOver label "Lahe: can't tell what is waiting".
